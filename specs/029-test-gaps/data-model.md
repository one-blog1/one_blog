# Data Model: 테스트 보강 (029)

DB 구조(ERD·Flyway)는 바꾸지 않는다. 테스트가 만드는 데이터와 배치 잠금이 쓰는 값만 적는다.

## 테스트 회원 (R1)

| 값 | 기본 (`signUp(email, nickname)`) | 새 오버로드 (`signUp(email, nickname, name, phone)`) |
|---|---|---|
| 이름 | 홍길동 | 테스트마다 지정 |
| 전화번호 | 010-1234-5678 | 테스트마다 지정 (숫자만 저장) |
| 비밀번호 | `Abcd123!` | 같음 |

블랙리스트는 `blog_blacklists.email_hash` 또는 `phone_hash`가 맞으면 막는다. 그래서 다음 조합으로 확인한다.

| 다시 가입한 회원 | 결과 |
|---|---|
| 같은 이메일, 다른 번호 | 막힘 |
| 다른 이메일, 같은 번호 | 막힘 |
| 다른 이메일, 다른 번호 | 참여 가능 |

## 시간 규칙과 바꿀 값 (R5)

| 규칙 | 근거 | 테스트에서 바꾸는 값 |
|---|---|---|
| 재설정 번호 30분 | SEC-05 | `verification_codes.expires_at` (재설정 용도 행) |
| 이메일 찾기 토큰 10분 | USR-08 | `account_lookup_tokens.expires_at` |
| 재확인 10분 | D-102 | 시각을 바꿀 수 있는 저장값이 없다(서명한 티켓). 발급된 티켓의 유효 시간(exp − iat)과 쿠키 Max-Age가 600초인지 보고, 테스트 키로 만든 만료 티켓은 거부되는지 본다 |
| 정지 기간 | BLG-13 | `blog_members.suspended_until` |
| 위임 7일 | BLG-08 | `runAll(만료 시각 + 1분)` |
| 폐쇄 1일 전 | BLG-09 | `runAll(close_scheduled_at - 1일)` |
| 30일 삭제 | 4.5 | `runAll(지운 시각 + 29일)` → 남음, `runAll(+31일)` → 지움 |
| 1년 보관 | 4.5, D-60 | `created_at`을 364일 전·366일 전으로 |
| 신고 2주 | 6.5 | `reports.created_at`을 13일 전·15일 전으로 |
| 블로그장 경고 1년 | ADM-07 | `sanctions`(OWNER_WARNING)의 `created_at`을 13개월 전으로 |

## 배치 잠금 (`shedlock` 테이블, FR-010)

| 컬럼 | 지금 | 고친 뒤 |
|---|---|---|
| `name` | `daily-batch` | 같음 |
| `lock_until` | 잡을 때 지금 + 최대 1시간. 풀면 **지금** | 잡을 때 같음. 풀면 **max(지금, 시작 + 5분)** |
| `locked_at` | 잡은 시각 | 같음 |
| `locked_by` | `호스트:PID` (운영 두 앱이 같음) | `호스트:PID:무작위 8자리` (앱마다 다름) |

잠금을 잡는 조건(`lock_until <= 지금`인 행만 가져감)은 그대로다.

## 삭제 배치가 지우는 것 (US5 확인 대상)

| 대상 | 언제 | 남기는 것 |
|---|---|---|
| 폐쇄 블로그의 글·댓글·카테고리·블로그 태그·구독·파일·블랙리스트·해제 문의 | 폐쇄 30일 뒤 | `blogs` 행 (주소 비우고 `deleted_at`) |
| 따로 지운 댓글 | 30일 뒤 | 살아 있는 답글이 달린 댓글 |
| 지운 표시 사진, 글에 안 붙은 업로드, 안 쓰는 배너 사진 | 30일 뒤 | 쓰고 있는 사진 |
| 탈퇴 회원 개인정보(이름·닉네임·전화번호·소개·프로필 사진) | 30일 뒤 | `users` 행 (상태 WITHDRAWN) |
| 신고·제재·관리자 기록 | 1년 뒤 | 1년 안 된 기록 |
| 알림 | 회원이 고른 보관 기간(30일·7일) 뒤 | 기간 안 알림 |
| 인증번호·임시 토큰 | 만료되거나 쓴 뒤 다음 배치 | 아직 쓸 수 있는 것 |
