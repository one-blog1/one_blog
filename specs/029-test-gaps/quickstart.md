# Quickstart: 테스트 보강 (029) 확인하기

## 1. 전체 테스트 (CI)

이 작업 공간에서는 테스트를 돌릴 수 없어 CI로 확인한다.

| 상황 | 하는 법 | 도는 테스트 |
|---|---|---|
| 028(CI 단계 나누기)이 `develop`에 합쳐지기 전 | `feature/test-gaps`에 push | 전체 (단위 + 통합) |
| 028이 합쳐진 뒤 | push하면 단위만 돈다. 통합은 `gh workflow run ci.yml --ref feature/test-gaps` (Actions → CI → Run workflow) | 직접 실행 = 전체 단계 |

통과 기준:
- 전체 테스트 통과 (SC-001)
- 테스트 단계 시간이 지금(약 5분)보다 5분 넘게 늘지 않음 (SC-005)

Mac에서 직접 돌릴 때:

```bash
./gradlew test                                          # 단위 + 통합 (로컬 MySQL, .env의 TEST_DB_*)
./gradlew test --tests '*SchedulerLockIntegrationTest'  # 하나만
```

## 2. 배치 잠금 (FR-010)

1. `SchedulerLockIntegrationTest`만 먼저 올린다(코드 수정 전). "A가 풀어도 5분 안에는 B가 못 잡는다"가 **실패**해야 한다.
2. `SchedulerLock`·`DailyBatch`를 고쳐 올린다. 전부 **통과**해야 한다.

## 3. 규칙을 깨면 실패하는지 (SC-003)

임시 브랜치 `feature/test-gaps-mutation`을 만들고, 아래 7가지를 한 커밋으로 일부러 깬다. CI에서 오른쪽 테스트가 모두 실패하는지 본 뒤 브랜치를 지운다. 결과는 `traceability.md`에 적는다.

| 깨는 것 | 실패해야 하는 테스트 |
|---|---|
| 블랙리스트 비교에서 이메일 조건 빼기 (전화번호만 비교) | 재가입 블랙리스트(같은 이메일·다른 번호) |
| 가입 비밀번호 규칙 검사 빼기 | 가입 입력 검사(비밀번호만 틀림) |
| `anyRequest().denyAll()`을 `permitAll()`로 | 정하지 않은 주소는 401 |
| 신고 목록에서 "본인 신고 제외" 조건 빼기 | 신고 대상 부블로그장은 자기 신고를 못 본다 |
| 블로그 검색에서 블로그 태그 조건 빼기 | 태그에만 있는 단어로 블로그 검색 |
| 차단할 때 팔로우 지우기 빼기 | 차단하면 팔로우가 0건 |
| (오류 코드) 닉네임 중복 응답의 오류 코드 바꾸기 | 오류 코드를 확인하는 수정된 테스트 |

## 4. 대조표

`traceability.md`에 분석 1~3번 항목마다 다음을 적는다 (FR-009, SC-002).

- 확인하는 테스트 (클래스.메서드)
- 3번 확인 결과 (US1)
- 만들지 못했거나 `@Disabled`로 둔 경우 그 이유
