## User Scenarios & Testing *(mandatory)*

### User Story 1 - 블로그 만들기 (Priority: P1)

로그인한 회원이 메인블로그에서 "블로그 만들기"를 누르고 블로그 이름, 주소, 소개, 대표 이미지, 태그, 공개 범위(공개·일부 공개·비공개), 참여 방식(자유·승인제)을 정해 블로그를 만든다. 만든 회원은 그 블로그의 블로그장이 되고, 만들고 나면 새 블로그의 첫 화면(`/blog/{주소}`)으로 이동한다.

**Why this priority**: 블로그가 있어야 참여(003)와 글쓰기(004)를 할 수 있다. 이 플랫폼의 핵심 모듈이다 (constitution II 1단계).

**Independent Test**: 회원으로 로그인해 블로그를 만들고, 그 블로그의 첫 화면이 열리며 만든 회원이 블로그장으로 표시되는지 확인한다. 목록 기능 없이도 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 이름·주소·공개 범위·참여 방식을 입력하고 만들기를 누르면, **Then** 블로그가 만들어지고 `/blog/{주소}` 첫 화면으로 이동하며, 만든 회원이 그 블로그의 블로그장이 된다.
2. **Given** 블로그 만들기 화면, **When** 주소를 입력하면, **Then** 사용할 수 있는 주소인지(형식, 중복, 예약어) 만들기 전에 바로 확인할 수 있다.
3. **Given** 블로그 만들기 화면, **When** 이미 쓰이는 주소, 예약어(main, admin, api, login, signup, search 등), 규칙(영문 소문자·숫자·- 3~30자)에 맞지 않는 주소를 넣으면, **Then** 이유가 보이고 만들어지지 않는다.
4. **Given** 블로그 만들기 화면, **When** 대표 이미지로 jpg·jpeg·png·gif·webp 중 3MB 이하 파일 1장을 올리면, **Then** 미리보기가 보이고 블로그에 대표 이미지로 저장된다.
5. **Given** 블로그 만들기 화면, **When** 허용하지 않는 형식(svg, pdf, 확장자만 바꾼 실행 파일 등)이나 3MB를 넘는 파일을 올리면, **Then** 거부되고 이유가 보인다.
6. **Given** 블로그 만들기 화면, **When** 태그를 `#맛집`, ` 서울 여행 `, `Java`, `java`처럼 넣으면, **Then** `맛집`, `서울_여행`, `java`로 정리되어 중복 없이 저장된다 (6.4).
7. **Given** 블로그 만들기 화면, **When** 태그를 11개 이상 넣거나 규칙(1~20자, 한글·영문·숫자·_)에 맞지 않는 태그를 넣으면, **Then** 이유가 보이고 만들어지지 않는다.
8. **Given** 공개 범위를 "일부 공개"로 고른 회원, **When** 블로그를 만들면, **Then** 블로그 주소와 별개인 무작위 값이 들어간 공유 링크가 만들어지고, 블로그장은 블로그 첫 화면에서 그 링크를 복사할 수 있다.
9. **Given** 로그인하지 않은 방문자 또는 메인 관리자 계정, **When** 블로그 만들기를 시도하면, **Then** 만들 수 없다 (2장, D-90).

### User Story 2 - 블로그 생성 개수 제한 (Priority: P1)

회원 한 명이 만들 수 있는 블로그 수를 제한한다. 공개 블로그(일부 공개 포함)는 3개, 비공개 블로그는 5개까지다. 동시에 여러 번 눌러도 제한을 넘지 않는다.

**Why this priority**: 블로그를 마구 만들고 방치하는 것을 막는 규칙이라 블로그 만들기와 함께 있어야 한다 (BLG-10, D-04). 나중에 붙이면 이미 제한을 넘은 데이터가 생긴다.

**Independent Test**: 한 회원으로 공개 3개, 일부 공개를 섞어 만든 뒤 4번째 공개·일부 공개 블로그가 거부되는지, 비공개는 5개까지 되는지, 만들기 요청을 동시에 여러 번 보내도 제한을 넘지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개 블로그 2개와 일부 공개 블로그 1개를 가진 회원, **When** 공개 또는 일부 공개 블로그를 하나 더 만들려고 하면, **Then** "공개 블로그는 3개까지 만들 수 있습니다" 같은 안내가 보이고 만들어지지 않는다 (D-51).
2. **Given** 공개 블로그 3개를 가진 회원, **When** 비공개 블로그를 만들면, **Then** 만들어진다 (공개와 비공개는 따로 센다).
3. **Given** 비공개 블로그 5개를 가진 회원, **When** 비공개 블로그를 하나 더 만들려고 하면, **Then** 안내가 보이고 만들어지지 않는다.
4. **Given** 공개 블로그 2개를 가진 회원, **When** 공개 블로그 만들기 요청이 거의 동시에 두 번 들어오면, **Then** 하나만 만들어지고 다른 하나는 개수 제한으로 거부된다 (D-68).
5. **Given** 운영자가 공개 블로그 제한값을 5로 바꾼 상태, **When** 공개 블로그 3개를 가진 회원이 하나 더 만들면, **Then** 만들어진다 (D-52).
6. **Given** 블로그 만들기 화면, **When** 회원이 화면을 열면, **Then** 지금 몇 개를 만들었고 몇 개 더 만들 수 있는지(공개·비공개 각각) 보인다.

### User Story 3 - 메인 화면의 블로그 목록 (Priority: P2)

누구나(비회원 포함) 메인 화면에서 공개 블로그 목록을 본다. 최신순과 인기순(멤버 수가 많은 순)으로 정렬을 바꿀 수 있고, 번호 페이지로 넘기며, 한 페이지에 10·20·30개 중 고를 수 있다. 블로그를 누르면 그 블로그로 이동한다.

**Why this priority**: 만든 블로그를 다른 회원이 찾아 들어와야 참여(003)가 의미 있다. 블로그 만들기(P1) 다음으로 필요하다.

**Independent Test**: 공개·일부 공개·비공개 블로그를 섞어 만든 뒤, 비회원으로 메인 화면에서 공개 블로그만 보이는지, 정렬과 페이지 넘기기가 규칙대로 동작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개·일부 공개·비공개 블로그가 섞여 있음, **When** 누구든 메인 화면의 블로그 목록을 보면, **Then** 공개 블로그만 보이고 일부 공개·비공개 블로그는 보이지 않는다 (BLG-02, D-49).
2. **Given** 블로그 목록, **When** 처음 들어오면, **Then** 최신순으로 한 페이지에 10개가 보인다 (6.6, D-06).
3. **Given** 블로그 목록, **When** 인기순을 고르면, **Then** 멤버 수가 많은 순서로 보이고, 멤버 수가 같으면 최근에 만든 블로그가 먼저 보인다 (D-89).
4. **Given** 블로그 목록, **When** 한 페이지 개수를 20 또는 30으로 바꾸거나 페이지 번호를 누르면, **Then** 고른 개수와 페이지대로 보이고, 전체 페이지 수가 보인다 (D-76).
5. **Given** 블로그 목록의 한 항목, **When** 누르면, **Then** 그 블로그의 첫 화면(`/blog/{주소}`)으로 이동한다.
6. **Given** 블로그 목록의 각 항목, **When** 화면에 보일 때, **Then** 블로그 이름, 소개(길면 줄임), 대표 이미지(없으면 기본 이미지), 태그, 멤버 수, 블로그장 닉네임이 보인다.

### User Story 4 - 내 블로그 목록 (Priority: P2)

로그인한 회원이 "내 블로그"에서 내가 만든 블로그(블로그장)와 참여한 블로그를 나눠 본다. 누르면 해당 블로그로 이동한다. 내 블로그 목록에는 공개 범위와 상관없이 내가 속한 블로그가 모두 보인다.

**Why this priority**: 회원이 자기 블로그로 들어가는 입구다. 일부 공개·비공개 블로그는 목록에 나오지 않으므로 이 화면이 없으면 블로그장도 자기 비공개 블로그를 찾기 어렵다.

**Independent Test**: 공개·일부 공개·비공개 블로그를 하나씩 만든 회원으로 로그인해 "내가 만든 블로그"에 세 개가 모두 보이고, 각 항목을 누르면 블로그 첫 화면이 열리는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 블로그를 만든 회원, **When** 내 블로그 화면을 열면, **Then** "내가 만든 블로그"에 공개 범위와 상관없이 내가 블로그장인 블로그가 모두 보이고, 각 항목에 공개 범위가 표시된다.
2. **Given** 다른 블로그의 멤버인 회원, **When** 내 블로그 화면을 열면, **Then** "참여한 블로그"에 그 블로그가 따로 보인다 (참여 기능은 003에서 만들며, 그 전까지는 이 칸이 비어 있다).
3. **Given** 만든 블로그도 참여한 블로그도 없는 회원, **When** 내 블로그 화면을 열면, **Then** 비어 있다는 안내와 블로그 만들기 버튼이 보인다.
4. **Given** 로그인하지 않은 방문자, **When** 내 블로그 화면에 들어가려고 하면, **Then** 로그인 화면으로 이동한다.

### User Story 5 - 공개 범위에 따른 블로그 첫 화면 접근 (Priority: P2)

블로그 첫 화면(`/blog/{주소}`)에는 블로그 이름, 소개, 대표 이미지, 태그, 블로그장 닉네임, 멤버 수가 보인다. 누가 들어올 수 있는지는 공개 범위가 정한다. 공개는 누구나, 일부 공개는 공유 링크로 들어온 사람과 멤버, 비공개는 멤버만 볼 수 있다. 글 목록은 004에서 이 화면에 붙인다.

**Why this priority**: 비공개 블로그를 만들 수 있게 하면서 접근을 막지 않으면 비공개 내용이 바로 샌다. 블로그 만들기와 같은 기능 안에서 지켜야 한다 (SEC-07).

**Independent Test**: 공개·일부 공개·비공개 블로그를 하나씩 만든 뒤, 비회원·다른 회원·블로그장으로 각각 주소, 공유 링크로 들어가 보이는지 막히는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개 블로그, **When** 비회원을 포함한 누구든 `/blog/{주소}`로 들어가면, **Then** 블로그 첫 화면이 보인다.
2. **Given** 일부 공개 블로그, **When** 멤버가 아닌 사람이 주소만으로 들어가면, **Then** 블로그 내용은 보이지 않고 "링크가 있어야 볼 수 있는 블로그입니다" 같은 안내가 보인다.
3. **Given** 일부 공개 블로그, **When** 비회원을 포함한 누구든 공유 링크로 들어가면, **Then** 블로그 첫 화면이 보인다 (D-50). 이때 자동으로 구독되지 않는다.
4. **Given** 비공개 블로그, **When** 멤버가 아닌 사람(비회원 포함)이 주소로 들어가면, **Then** 블로그 내용은 보이지 않고 "비공개 블로그입니다" 같은 안내가 보인다.
5. **Given** 비공개·일부 공개 블로그, **When** 그 블로그의 블로그장이 주소로 들어가면, **Then** 블로그 첫 화면이 보인다.
6. **Given** 없는 주소, **When** 누구든 `/blog/{없는 주소}`로 들어가면, **Then** "블로그를 찾을 수 없습니다" 안내가 보인다.
7. **Given** 일부 공개 블로그의 블로그장, **When** 블로그 첫 화면을 보면, **Then** 공유 링크 복사 버튼이 보인다. 비공개 블로그에는 공유 링크와 공유 버튼이 없다 (BLG-01).

### Edge Cases

- 두 회원이 거의 동시에 같은 주소로 블로그를 만들면 한 명만 성공하고, 다른 한 명에게는 이미 쓰이는 주소라는 안내가 보인다.
- 주소를 대문자로 입력하면 소문자로 바꿔 확인하고 저장한다. 앞뒤 공백은 제거한다.
- 주소가 `-`로 시작하거나 끝나거나 `--`처럼 이어지면 거부한다.
- 블로그 이름이 같은 블로그는 여러 개 있을 수 있다 (6.5). 블로그는 주소로 구분한다.
- 대표 이미지만 올리고 블로그 만들기를 취소하면 그 이미지는 어떤 블로그에도 연결되지 않고, 화면에도 보이지 않는다.
- 사진의 위치 정보(EXIF GPS 등)는 저장할 때 지운다 (6.3).
- 공유 링크의 무작위 값이 틀리면 주소만으로 들어온 것과 똑같이 안내만 보인다(값이 틀렸는지 블로그가 있는지 구분해 알려주지 않는다).
- 비공개 블로그 주소로 들어온 비멤버에게 블로그 이름·소개·대표 이미지·태그·블로그장을 보여주지 않는다.
- 목록을 보는 중에 새 블로그가 생겨 페이지 경계가 밀리는 것은 허용한다(다음 페이지에서 한 개가 겹쳐 보일 수 있음).
- 페이지 번호가 전체 페이지보다 크거나 한 페이지 개수가 10·20·30이 아니면 기본값(1페이지, 10개)으로 보여준다.
- 블로그장 닉네임, 블로그 이름, 소개, 태그에 `<script>` 같은 값이 들어 있어도 화면에는 글자 그대로 보인다 (SEC-06).

## Requirements *(mandatory)*

### Functional Requirements

**블로그 만들기 (BLG-01)**

- **FR-001**: 로그인한 일반 회원은 블로그 이름, 주소, 소개, 대표 이미지, 태그, 공개 범위, 참여 방식을 정해 블로그를 만들 수 있어야 한다. 필수는 이름, 주소, 공개 범위, 참여 방식이다.
- **FR-002**: 블로그를 만든 회원은 그 블로그의 블로그장이 되고, 그 블로그의 멤버 수는 1로 시작해야 한다. 역할은 회원 계정이 아니라 블로그별로 저장한다 (constitution IV, 2장).
- **FR-003**: 비회원과 메인 관리자 계정은 블로그를 만들 수 없어야 한다 (2장, D-90).
- **FR-004**: 블로그 이름은 앞뒤 공백을 뺀 1~50자이고 다른 블로그와 같아도 된다 (6.5).
- **FR-005**: 블로그 소개는 0~500자이다.
- **FR-006**: 공개 범위는 공개·일부 공개·비공개 중 하나, 참여 방식은 자유·승인제 중 하나이며 기본값은 공개·자유다 (D-49, D-01).

**블로그 주소 (6.5, D-70)**

- **FR-007**: 블로그 주소는 영문 소문자·숫자·-로 된 3~30자이며, `-`로 시작하거나 끝날 수 없고 `-`를 두 번 이어 쓸 수 없다. 입력한 대문자는 소문자로 바꿔 처리한다.
- **FR-008**: 블로그 주소는 다른 블로그와 겹칠 수 없고, 사이트 주소와 겹치는 예약어(main, admin, api, login, signup, search, blog, my, css, js, images, files, error 등)는 쓸 수 없어야 한다 (6.5).
- **FR-009**: 회원은 블로그를 만들기 전에 주소를 쓸 수 있는지 확인할 수 있어야 하고, 만들 때 서버가 다시 확인해야 한다.
- **FR-010**: 블로그 주소는 `/blog/{주소}` 형태로 쓰인다 (D-70).

**대표 이미지 (6.3, SEC-08)**

- **FR-011**: 대표 이미지는 1장, 3MB 이하이고 jpg·jpeg·png·gif·webp만 받아야 한다.
- **FR-012**: 시스템은 확장자, 파일 형식 표시, 파일 앞부분의 실제 내용을 모두 확인해, 셋 중 하나라도 맞지 않으면 거부해야 한다 (SEC-08).
- **FR-013**: 시스템은 파일을 원래 이름이 아닌 무작위 이름으로 저장하고 원래 이름은 기록으로만 남기며, 사진의 위치 정보를 지운 뒤 저장해야 한다 (6.3).
- **FR-014**: 대표 이미지를 고르지 않으면 기본 이미지를 보여준다.

**태그 (6.4, D-88)**

- **FR-015**: 블로그에는 태그를 0~10개 달 수 있다.
- **FR-016**: 태그는 앞의 `#`과 앞뒤 공백을 지우고, 가운데 공백은 `_`로 바꾸며, 영문은 소문자로 바꿔 저장해야 한다. 정리한 결과 같은 태그는 하나로 합친다.
- **FR-017**: 정리한 태그는 1~20자이고 한글·영문·숫자·_만 써야 한다. 맞지 않는 태그가 하나라도 있으면 블로그를 만들지 않고 어느 태그가 틀렸는지 보여야 한다.
- **FR-018**: 블로그 태그와 글 태그는 같은 태그 목록을 함께 쓴다 (D-88).

**일부 공개 공유 링크 (BLG-01, D-49, D-50)**

- **FR-019**: 일부 공개 블로그를 만들면 블로그 주소와 별개인, 추측할 수 없는 무작위 값을 넣은 공유 링크를 만들어야 한다. 공개·비공개 블로그에는 공유 링크가 없다.
- **FR-020**: 공유 링크로 들어온 사람(비회원 포함)은 그 일부 공개 블로그를 볼 수 있어야 하고, 자동으로 구독되지 않아야 한다 (D-50).

**생성 개수 제한 (BLG-10, D-51, D-52, D-68)**

- **FR-021**: 회원 한 명은 공개 블로그(일부 공개 포함)를 3개, 비공개 블로그를 5개까지 만들 수 있어야 한다. 셀 때는 그 회원이 블로그장인, 폐쇄되지 않은 블로그를 센다.
- **FR-022**: 두 제한값은 운영 설정으로 바꿀 수 있어야 하고(공개는 5개까지 늘릴 예정), 코드 수정 없이 서버 재시작으로 적용된다.
- **FR-023**: 같은 회원의 만들기 요청이 동시에 여러 번 들어와도 제한을 넘는 블로그가 만들어지지 않아야 한다 (D-68).
- **FR-024**: 블로그 만들기 화면은 공개·비공개 각각 지금 만든 개수와 남은 개수를 보여야 한다.

**블로그 목록 (BLG-02)**

- **FR-025**: 누구나(비회원 포함) 메인 화면에서 블로그 목록을 볼 수 있어야 한다. 목록에는 공개 블로그만 나오고, 일부 공개·비공개·관리자가 숨긴 블로그·폐쇄된 블로그는 나오지 않아야 한다.
- **FR-026**: 목록은 최신순(기본)과 인기순(멤버 수가 많은 순, 같으면 최신순)으로 정렬할 수 있어야 한다 (D-89).
- **FR-027**: 목록은 번호 페이지로 넘기고, 한 페이지에 10(기본)·20·30개 중 고를 수 있어야 한다. 전체 페이지 수를 보여준다 (D-06, D-76, 6.6).
- **FR-028**: 목록의 각 블로그에는 이름, 소개(길면 줄임), 대표 이미지, 태그, 멤버 수, 블로그장 닉네임이 보이고, 누르면 그 블로그로 이동해야 한다.

**내 블로그 목록 (BLG-06)**

- **FR-029**: 로그인한 회원은 내가 블로그장인 블로그와 멤버로 참여한 블로그를 나눠 볼 수 있어야 한다. 공개 범위와 상관없이 내가 속한 폐쇄되지 않은 블로그가 모두 보이고, 각 항목에 공개 범위가 표시된다.
- **FR-030**: 내 블로그 목록의 항목을 누르면 그 블로그로 이동해야 한다.

**블로그 첫 화면과 접근 (BLG-01, SEC-07)**

- **FR-031**: 블로그 첫 화면은 블로그 이름, 소개, 대표 이미지, 태그, 블로그장 닉네임, 멤버 수를 보여야 한다.
- **FR-032**: 시스템은 블로그를 볼 수 있는지를 요청마다 서버에서 판단해야 한다. 공개는 누구나, 일부 공개는 맞는 공유 링크로 들어온 사람과 그 블로그의 멤버, 비공개는 그 블로그의 멤버만 볼 수 있다. 블로그장과 멤버 여부는 브라우저가 보낸 정보가 아니라 저장된 멤버십으로 확인한다 (SEC-07, constitution III).
- **FR-033**: 볼 수 없는 사람에게는 블로그의 이름·소개·이미지·태그·블로그장 등 어떤 내용도 보내지 않고, 일부 공개는 "링크가 필요함", 비공개는 "비공개 블로그" 안내만 보여야 한다. 없는 주소는 "블로그를 찾을 수 없음"을 보여야 한다.
- **FR-034**: 일부 공개 블로그의 블로그장과 멤버에게는 첫 화면에 공유 링크 복사 버튼이 보여야 하고, 비공개 블로그에는 공유 버튼이 없어야 한다 (BLG-01).

**공통**

- **FR-035**: 상태를 바꾸는 요청(블로그 만들기, 이미지 올리기)은 위조 요청 방지 검사를 거쳐야 한다 (SEC-10).
- **FR-036**: 블로그 이름·소개·태그·닉네임 등 사용자 입력은 화면에 문자 그대로 보여야 하며, 실행 가능한 코드로 해석되지 않아야 한다 (SEC-06).

### Key Entities *(include if feature involves data)*

- **블로그(blogs)**: 주소, 이름, 소개, 대표 이미지, 공개 범위, 참여 방식, 공유 링크 값, 상태(운영 중·폐쇄 예정·폐쇄), 관리자 숨김 여부, 멤버 수, 만든·고친·삭제 시각. 이번 기능에서는 폐쇄 관련 값은 쓰지 않고 운영 중 상태로만 만든다.
- **블로그 멤버십(blog_members)**: 회원과 블로그를 잇고 블로그별 역할(블로그장·부블로그장·멤버)과 상태를 둔다. 이번 기능에서는 블로그를 만들 때 블로그장 행만 만든다.
- **태그(tags)**: 글과 블로그가 함께 쓰는 태그 이름 목록. 이름은 겹치지 않는다.
- **블로그 태그(blog_tags)**: 블로그와 태그를 잇는다.
- **업로드 파일(files)**: 올린 회원, 용도(이번 기능은 블로그 대표 이미지), 저장 이름, 원래 이름, 형식, 크기. 글 이미지(005)와 프로필 사진(009)도 나중에 같은 곳을 쓴다.

모든 테이블은 Crowfoot ERD "One Blog 메인블로그"의 `blogs`, `blog_members`, `tags`, `blog_tags`, `files`를 따른다 (constitution IV).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 블로그를 만드는 회원이 만들기 화면에 들어와 블로그 첫 화면을 보기까지 2분 안에 끝낼 수 있다.
- **SC-002**: 메인 블로그 목록과 내 블로그 목록은 블로그가 1만 개 있어도 2초 안에 보인다 (4.2 성능 목표).
- **SC-003**: 같은 회원이 만들기 요청을 동시에 10번 보내도 제한 개수를 넘는 블로그가 0개다.
- **SC-004**: 비회원과 다른 회원이 비공개 블로그와 (링크 없는) 일부 공개 블로그의 내용(이름·소개·이미지·태그)을 화면이나 응답에서 하나도 볼 수 없다.
- **SC-005**: 메인 블로그 목록에 일부 공개·비공개 블로그가 한 개도 나오지 않는다.
- **SC-006**: 허용하지 않는 형식과 3MB를 넘는 파일, 확장자만 바꾼 파일은 100% 거부된다.
- **SC-007**: 블로그를 만든 회원은 공개 범위와 상관없이 내 블로그 목록에서 자기 블로그를 100% 찾을 수 있다.

## Assumptions

- 블로그를 만들면 바로 그 블로그 첫 화면으로 이동한다.
- 블로그 이름 1~50자, 소개 0~500자는 Crowfoot ERD의 컬럼 크기를 따른다. 요구사항에 숫자가 없어 ERD 크기를 상한으로 쓴다.
- 대표 이미지는 블로그를 만들기 전에 먼저 올리고, 만들 때 그 이미지를 연결한다. 연결되지 않은 이미지를 지우는 일은 이번 범위가 아니다(04:00 배치, 012).
- 블로그 주소 예약어는 6.5의 예시(main, admin, api, login, signup, search)에 지금 사이트가 쓰는 경로 이름을 더해 서버 설정에 목록으로 둔다. 예약어 비교는 대소문자를 구분하지 않는다.
- 공유 링크 형태는 `/blog/{주소}?key={무작위 값}`처럼 주소에 무작위 값을 붙이는 방식으로 하고, 정확한 모양은 plan에서 정한다.
- 블로그 첫 화면은 이번에는 블로그 정보만 보여주고, 글 목록(004), 참여 신청 버튼(003), 구독하기 버튼(009)은 해당 기능에서 붙인다.
- 폐쇄 예정(CLOSING) 블로그는 이번 기능 시점에 생길 수 없지만, 셀 때와 목록에서는 "폐쇄되지 않은 블로그"로 다룬다(D-67: 폐쇄 예정 중에도 평소처럼 운영).
- 정지·블랙리스트처럼 블로그 입장을 막는 규칙(BLG-11, BLG-13)은 해당 테이블이 생기는 013에서 접근 판단에 더한다.
- 화면은 PC와 모바일 모두에서 쓸 수 있어야 한다 (4.2).

## 후속 작업 (constitution II)

이번 기능에서 일부러 뺀 항목이다. 화살표 뒤 번호는 [docs/roadmap.md](../../docs/roadmap.md)에서 다룰 기능이다.

- 참여 신청·승인과 참여 버튼, 내 블로그의 "참여한 블로그" 채우기 (BLG-04, 05) → 003
- 블로그 첫 화면의 글 목록 (BRD-02) → 004
- 블로그 구독과 "구독하기" 버튼, 구독 목록으로 다시 들어가기 (SOC-01, D-50) → 009
- 블로그 검색: 이름·소개·태그 (BLG-03) → 010
- 블로그 정보 수정(이름·소개·대표 이미지), 공개 범위·참여 방식 변경과 비공개 전환 시 구독자 알림, 공유 링크 다시 만들기 (BLG-01, 2장 블로그장 표) → 로드맵에 아직 없음. 번호를 정해 로드맵에 추가해야 함
- 연결되지 않은 대표 이미지 정리 (4.5) → 012
- 정지된 멤버·블랙리스트의 블로그 입장 막기 (BLG-11, BLG-13) → 013
- 관리자의 블로그 숨김 (ADM-02) → 007
- 태그 금칙어 (6.4, 보류) → 팀 확정 후
