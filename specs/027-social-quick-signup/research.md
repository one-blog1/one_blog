# Research: 소셜 간편 가입

## R1. 카카오 이메일

- **Decision**: scope를 `profile_nickname, account_email`로. 인증 표시(`is_email_valid`·`is_email_verified`)가 둘 다 true일 때만 믿는다 (지금 코드 그대로).
- **Rationale**: 비즈 앱 등록·이메일 필수 동의 완료. 이름·전화번호는 사업자 비즈 앱만 받을 수 있어 화면에서 받는다.
- **Alternatives**: 카카오 싱크(간편가입) — 사업자 필요, 제외.

## R2. 네이버 이메일·이름·휴대전화

- **Decision**: `response.email`을 인증된 것으로 본다(`emailVerified=true`). `response.name`, `response.mobile`을 쓴다.
- **Rationale**: 사용자 결정("믿고 바로 가입"). 네이버는 인증 여부 값을 주지 않지만 네이버 계정 이메일은 네이버가 확인한 주소다.
- **위험**: 네이버 계정 이메일이 바뀌었거나 남의 주소면 그 주소로 가입될 수 있다. 같은 이메일 회원이 있으면 저절로 붙이지 않으므로 기존 계정을 뺏기지는 않는다.
- **전화번호 정리**: 숫자만 남김. `+82`로 시작하면 `0`으로 바꿈(`+82 10-1234-5678` → `01012345678`). 결과가 10~11자리가 아니면 버리고 화면에서 받는다.

## R3. 구글 이름

- **Decision**: `name`을 이름으로. 닉네임 후보는 `given_name` (지금 그대로).

## R4. 이름·전화번호 가리기와 원래 값 쓰기

- **Decision**: 화면에는 `홍*동`, `010-****-5678` 같은 가린 값만 내려 준다(4.4, constitution III). 가입 때 서버는 쿠키의 원래 값을 쓰고, 요청의 같은 칸은 무시한다.
- **Rationale**: 화면이 원래 값을 몰라도 가입할 수 있다. 사용자가 화면에서 값을 바꿔 사이트가 준 실명을 덮어쓰지 못한다.
- **가리는 규칙**: 이름 2자 `홍*`, 3자 이상은 첫·끝 글자만 남김. 전화번호는 가운데 자리를 `*`. 이메일은 앞 2자 + `***@도메인`.
- **쿠키**: 서명만 되고 암호화는 안 된 JWT라 본인 브라우저에서는 값이 보인다. 본인 정보이고 HttpOnly·path `/api/auth`·15분이라 지금 이메일·이름을 담는 것과 같은 수준으로 본다.

## R5. 닉네임 정하기

- **Decision**: 기본은 사이트에서 받은 닉네임(카카오 닉네임, 네이버 별명, 구글 given_name)을 그대로 가입 화면 닉네임 칸에 채운다. 칸은 늘 고칠 수 있고 "중복 확인" 단추도 그대로 둔다. 가입 뒤에도 내 정보에서 바꿀 수 있다.
- 받은 닉네임을 그대로 쓸 수 없을 때만 서버가 고쳐 채운다: 한글·영문·숫자만 남기고 12자로 자름 → 2자 미만이거나 금지어면 `회원` + 숫자 4자리 → 이미 있으면 뒤에 2, 3, … (12자를 넘으면 앞을 줄임) → 열 번 안에 못 찾으면 `회원` + 무작위 숫자.
- **Rationale**: 지금은 쓸 수 없으면 빈칸이라 사용자가 꼭 입력해야 했다. 미리 채워 두면 네이버는 동의만으로 끝난다.
- **경합**: 화면을 연 뒤 같은 닉네임이 먼저 가입되면 지금처럼 `NICKNAME_UNAVAILABLE`로 알려 준다.

## R6. 약관 동의

- **Decision**: 로그인 화면은 그대로. 가입 화면의 기존 체크(전체 동의, 이용약관, 개인정보)를 그대로 쓴다. 처음 온 사람만 이 화면을 본다.
- **Alternatives**: 로그인 화면에 미리 체크 — 사용자가 빼기로 함.

## R7. 같은 이메일 회원

- **Decision**: 지금도 `emailInUse`를 알려 준다(사이트가 인증한 이메일일 때만). 바뀌는 점: 화면은 이메일을 가려 보여 주고 비밀번호 칸만 둔다. `/api/auth/social/link`는 이메일을 비워 보내면 쿠키의 이메일을 쓴다.
- **Rationale**: 사용자가 자기 이메일을 다시 칠 필요가 없다. 비밀번호 확인·잠금·Turnstile은 지금 로그인과 같다.
- **가입 여부 노출**: 사이트가 인증한 이메일의 주인에게만 알려 주므로 남의 가입 여부를 캐는 데 쓸 수 없다 (지금 규칙 유지).
