# Feature Specification: 소셜 간편 가입 (가입 화면 한 장)

**Feature Branch**: `feature/social-quick-signup` | **Created**: 2026-10-14 | **Status**: Confirmed (specify 확인 2026-10-14)

**Input**: "카카오 비즈 앱 등록, 이메일 필수 동의(닉네임 필수·프로필 사진 선택·이메일 필수)", "네이버에서 이름과 전화번호 추가", "원래 형식대로 이름과 전화번호를 받는 쪽으로", "소셜 이메일과 같은 이메일이 이미 있으면 이미 있다고 알림", 결정: 약관 동의는 소셜 로그인 후 처음 온 사람에게만 가입 화면에서 받음, 네이버 이메일은 믿고 그대로 씀

**관련 요구사항**: USR-01(가입), USR-02(이메일 인증), USR-09(소셜 로그인), 4.6(개인정보), D-126, 새 결정 D-139

## 바뀌지 않는 것

- 회원 정보는 지금과 같다: 이메일·이름·닉네임·휴대전화 번호 필수, 이름은 가입 뒤 바꿀 수 없음 (USR-01)
- DB 구조, 일반(이메일) 가입, 이메일 찾기(이름+전화번호), 블랙리스트(이름·이메일·전화번호 해시)는 그대로

## 사용자 시나리오

### US1 - 받을 수 있는 건 받아 오고, 빈칸만 묻기 (P1)

1. **Given** 로그인·가입 화면, **When** 카카오·네이버·구글로 처음 들어오면, **Then** 사이트에서 받은 값을 채운 가입 화면 한 장이 나온다. 이 화면에는 약관 동의와 빈칸만 있고, 동의(와 빈칸 입력) 후 "가입하기"를 누르면 가입·로그인된다.
2. 사이트별로 받는 값과 사용자가 넣을 칸:

| 사이트 | 받아 오는 값 | 사용자가 넣을 칸 |
|---|---|---|
| 네이버 | 이메일, 이름, 휴대전화, 별명 | 없음 (동의만) |
| 구글 | 이메일(인증 표시), 이름 | 휴대전화 |
| 카카오 | 이메일(인증 표시), 닉네임 | 이름, 휴대전화 |

3. 이메일 인증번호는 받지 않는다. 카카오는 인증 표시(is_email_valid·is_email_verified)가 있을 때, 구글은 email_verified일 때, 네이버는 받은 값을 그대로 믿는다. 카카오·구글에서 인증 표시가 없으면 지금처럼 인증번호로 확인한다(예외 흐름).
4. 닉네임은 사이트의 닉네임(카카오 닉네임, 네이버 별명, 구글 given_name)을 쓰고, 형식에 맞지 않거나 이미 있으면 서버가 쓸 수 있는 닉네임을 정한다(예: `길동` → `길동2`, 형식이 안 맞으면 `회원1234`). 빈칸 화면이 있으면 그 화면에서 바꿀 수 있고, 가입 뒤에도 내 정보에서 바꿀 수 있다.
5. 사이트가 준 이름·전화번호가 우리 형식에 맞지 않으면(이름 1~50자, 휴대전화 숫자 10~11자리) 빈칸으로 보고 화면에서 받는다. 네이버 휴대전화(`010-1234-5678`)는 숫자만 남겨 저장한다.

### US2 - 약관 동의는 처음 온 사람에게만, 가입 화면에서 (P1)

1. 로그인 화면은 지금 그대로 둔다(동의 체크를 두지 않는다).
2. 소셜 로그인 뒤 처음 온 사람이면 가입 화면에 "이용약관과 개인정보 처리방침에 동의합니다" 체크와 전문 보기 링크를 보여 준다. 체크해야 가입되고, 가입 때 동의 시각을 저장한다.
3. 빈칸이 없는 경우(네이버)에도 이 화면은 한 번 나온다. 받은 값을 보여 주고 동의 체크와 "가입하기"만 있다.
4. 이미 회원(소셜 연결됨)이면 이 화면 없이 바로 로그인된다.

### US3 - 같은 이메일의 회원이 이미 있을 때 (P1)

1. 사이트가 준 이메일로 가입한 계정이 이미 있으면 가입하지 않고 "이 이메일(ab***@…)로 가입한 계정이 이미 있습니다" 화면을 보여 준다.
2. 그 화면에서 비밀번호로 로그인하면 이 소셜 계정이 연결되고 다음부터 소셜로 바로 로그인된다(지금 기능). 저절로 연결하지는 않는다.
3. 비밀번호를 모르면 "비밀번호 찾기"로 갈 수 있다.

### Edge Cases

- 카카오 동의 화면에서 이메일 동의를 빼고 오면(필수라 보통 없음) 이메일 칸을 보여 주고 인증번호로 확인한다.
- 같은 휴대전화 번호의 회원이 있어도 가입은 된다(지금 규칙: 1차는 중복 허용).
- 가입 화면이 열린 뒤 15분이 지나면 소셜 로그인부터 다시(지금 규칙).
- 카카오 프로필 사진은 이번에는 쓰지 않는다. 기본 사진으로 가입하고 내 정보에서 바꾼다(사진 주소가 카카오 서버라 보안 헤더 CSP에 막힘. 우리 저장소로 받아 저장하는 것은 후속 작업).

## 요구사항

- **FR-001**: 카카오 요청 범위에 `account_email` 추가. 네이버는 개발자 화면 설정(이메일·이름·휴대전화·별명)을 그대로 받는다.
- **FR-002**: 네이버 `response.name`, `response.mobile`과 구글 `name`을 이름·전화번호로 쓴다. 형식이 맞지 않으면 버린다.
- **FR-003**: 소셜 가입 대기 정보(서명한 쿠키)에 이름·전화번호를 담는다. 받은 값은 화면에 보여 주되 이름·전화번호는 가려서(`홍*동`, `010-****-5678`) 보여 준다.
- **FR-004**: 처음 온 사람은 늘 가입 화면으로 보낸다. 화면에는 받은 값(가려서), 빈칸, 동의 체크만 둔다. 서버는 동의와 빈칸을 다시 확인한 뒤 가입하고 로그인 쿠키를 준다.
- **FR-005**: 닉네임 자동 정하기 (형식 맞추기, 겹치면 숫자 붙이기, 최대 12자, 금지어 피하기).
- **FR-006**: (빠짐) 로그인 화면 동의 체크와 동의 쿠키는 만들지 않는다.
- **FR-007**: 같은 이메일 회원이 있으면 "이미 있음" 화면(가린 이메일) + 비밀번호로 연결 + 비밀번호 찾기 링크.
- **FR-008**: 개인정보 처리방침에 카카오 이메일, 네이버 이름·휴대전화를 받는다고 적는다. 요구사항 USR-01·USR-09, 4.6, 8장 D-139.

## 성공 기준

- 네이버로 처음 온 사람은 입력 없이 동의 체크와 "가입하기"만으로 가입·로그인된다
- 구글은 휴대전화 한 칸, 카카오는 이름·휴대전화 두 칸만 넣고 가입된다
- 같은 이메일의 회원이 있으면 가입되지 않고 "이미 있음"을 본다
- 이미 연결된 소셜 회원은 지금처럼 바로 로그인된다
- 테스트: 사이트별 받은 값 → 빈칸 판단, 동의 없으면 가입 안 됨, 이메일 중복, 닉네임 겹침, 전화번호 형식
