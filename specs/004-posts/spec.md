# Feature Specification: 글 작성·조회·수정·삭제, 목록

**Feature Branch**: `main` | **Created**: 2026-10-07 | **Status**: Draft

**Input**: "004 글 작성·조회·수정·삭제, 목록 (BRD-01, BRD-02, 6.6). 블로그 멤버가 마크다운으로 글을 쓰고, 누구나(블로그를 볼 수 있는 사람) 읽는다. 수정은 작성자만, 삭제는 작성자와 글 관리 권한이 있는 블로그장·부블로그장. 블로그 공지. 목록은 최신순 번호 페이지(10·20·30). 글쓰기 중 로그인 연장과 만료 5분 전 안내(SEC-04, D-62). 후속: 이미지·에디터(005), 댓글·좋아요(006), 관리자 삭제·숨김(007), 카테고리·태그(008), 조회수·공유(014)"

**관련 요구사항**: BRD-01, BRD-02, SEC-04(글쓰기 중 연장), SEC-06, SEC-07, 6.6, D-05, D-06, D-07, D-33, D-58, D-62, D-64, D-76, D-92

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 멤버가 글을 쓰고 누구나 읽기 (Priority: P1)

블로그 멤버가 제목과 마크다운 본문으로 글을 쓴다. 블로그를 볼 수 있는 사람은 누구나 글을 읽는다.

**Acceptance Scenarios**:

1. **Given** 블로그 멤버, **When** 제목(1~30자)과 본문(1~5,000자)으로 저장하면, **Then** 글이 만들어지고 글 화면으로 이동한다.
2. **Given** 멤버가 아닌 회원·비회원·관리자, **When** 글을 쓰려 하면, **Then** 거부된다.
3. **Given** 공개 블로그의 글, **When** 비회원이 열면, **Then** 마크다운이 HTML로 보인다. 본문 안의 스크립트·위험한 링크는 실행되지 않는다 (SEC-06).
4. **Given** 비공개 블로그의 글, **When** 멤버가 아닌 사람이 열면, **Then** 비공개 안내만 보인다.

### User Story 2 - 작성자가 고치고, 작성자·블로그장이 지우기 (Priority: P1)

1. **Given** 내가 쓴 글, **When** 고치면, **Then** 바뀐다. 블로그장도 남의 글은 고칠 수 없다 (D-07).
2. **Given** 남의 글, **When** 글 관리 권한이 있는 블로그장·부블로그장이 지우면, **Then** "글을 정말 삭제하시겠습니까?" 확인 후 지워진다 (D-58, 6.3).
3. **Given** 블로그를 떠난 작성자의 글, **When** 누가 보면, **Then** 작성자가 "탈퇴한 계정"으로 보이고 작성자도 고칠 수 없다 (D-33).

### User Story 3 - 글 목록 (Priority: P2)

1. **Given** 글이 여러 개인 블로그, **When** 블로그 첫 화면을 열면, **Then** 최신순으로 10개씩, 번호 페이지로 보인다. 10·20·30개 중 고를 수 있다 (D-06, D-76).
2. **Given** 블로그 공지, **When** 목록을 보면, **Then** 공지(최근 5개)가 일반 글 위에 따로 보인다.

### User Story 4 - 글쓰기 중 로그인 연장 (Priority: P3)

1. **Given** "로그인 유지"를 체크하지 않은 회원이 글을 쓰는 중, **When** 입력을 계속하면, **Then** 30분이 지나도 로그아웃되지 않는다 (D-62).
2. **Given** 25분 동안 입력이 없음, **When** 시간이 지나면, **Then** "곧 로그인 시간이 끝나요"와 연장 버튼이 보인다 (만료 5분 전).
3. **Given** 쓰는 중, **When** 30초가 지나면, **Then** 이 브라우저에 임시 저장되고 다음에 열면 불러올지 묻는다 (6.6 임시저장).

### Edge Cases

- 지워진 글과 메인 공지는 블로그 글 주소로 열리지 않는다(404).
- 본문은 이모지 하나를 한 글자로 센다.
- 관리자는 블로그 글 API로 지우지 않고 관리자 화면(007)을 쓴다.

## Requirements *(mandatory)*

- **FR-001**: 활성 멤버만 글을 쓸 수 있어야 한다. 관리자 계정은 블로그 글을 쓸 수 없다 (D-90).
- **FR-002**: 제목 1~30자, 본문 1~5,000자(공백·마크다운 기호 포함)를 서버에서 검사해야 한다 (6.6, D-92).
- **FR-003**: 본문은 마크다운 원문으로 저장하고, 보여줄 때 서버가 HTML로 바꾼 뒤 허용 목록으로 걸러야 한다. 화면은 이 본문에만 innerHTML을 쓴다 (SEC-06, D-64).
- **FR-004**: 고치기는 작성자 본인만, 그 블로그의 멤버로 남아 있을 때만 할 수 있다 (D-07, D-33).
- **FR-005**: 지우기는 작성자 본인, 글 관리 권한이 있는 블로그장·부블로그장이 할 수 있다. 지운 주체를 기록한다 (D-58, 작성자 알림은 011).
- **FR-006**: 지운 글은 30일 동안 보관하되 화면과 API에 보이지 않아야 한다 (4.5, 완전 삭제 배치는 012).
- **FR-007**: 블로그 공지는 글 관리 권한이 있어야 쓰고, 목록 위에 따로 보여야 한다.
- **FR-008**: 목록은 최신순, 10·20·30개 번호 페이지 (BRD-02).
- **FR-009**: 볼 수 있는지는 002의 블로그 접근 규칙을 따른다 (SEC-07).
- **FR-010**: 글쓰기 화면은 입력 중 로그인을 연장하고, 만료 5분 전에 안내해야 한다 (SEC-04, D-62).

### Key Entities

- **글(posts)**: ERD 그대로. 이번에는 `category_id`를 비워 둔다(008에서 외래 키).

## Success Criteria

- **SC-001**: 본문에 넣은 스크립트가 어떤 화면에서도 실행되지 않는다.
- **SC-002**: 작성자가 아닌 사람이 글을 고칠 수 있는 경로가 없다.
- **SC-003**: 목록은 글 1만 개에서도 2초 안에 보인다 (인덱스 `idx_posts_blog_id_created_at`).

## Assumptions

- 4.4의 "작성자" 표시는 닉네임이다. 탈퇴한 회원은 "탈퇴한 회원", 블로그를 떠난 작성자는 "탈퇴한 계정".
- 글 주소는 `/blog/{주소}/posts/{번호}`, 글쓰기는 `/blog/{주소}/write`.
