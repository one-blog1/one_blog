# Feature Specification: SNS 공유 2차

**Feature Branch**: `feature/sns-share`

**Created**: 2026-10-16

**Status**: 확인됨 (2026-10-16)

**범위 (사용자 결정, 2026-10-16)**: 키 없이 바로 되는 **X, 페이스북, 텔레그램, 기기 공유** 4개를 먼저 한다. 카카오톡은 카카오 JavaScript 키·도메인 등록이 준비되면 다음 스펙에서 한다. 인스타그램은 웹 공유 화면이 없어 기기 공유로 대신한다.

**Input**: "SNS 공유 2차 (BRD-07, 6.2): 글 화면에서 링크 복사 말고도 카카오톡, X, 페이스북, 인스타그램, 텔레그램으로 공유. 카카오톡은 Kakao JavaScript SDK(6.2 확정). 미리보기는 이미 있는 Open Graph 태그(D-59) 사용. 공유 수 집계 안 함."

**관련 요구사항**: BRD-07(공유), 6.2 SNS 공유(공유 수단 2차, 카카오톡 SDK, 미리보기, 집계 안 함), D-59·D-66(미리보기), BLG-01·D-49(공개 범위·공유 링크), SEC-06·SEC-12(외부 스크립트·보안 헤더), constitution III·V

## 지금 상태

- 글 화면에는 **링크 복사** 버튼 하나만 있다(1차). 일부 공개 블로그 글은 복사한 링크에 공유 key가 들어간다.
- 서버가 글 화면에 미리보기 태그를 이미 채운다(D-66): 주소 → 제목·작성자·블로그 이름 → 이미지(글의 첫 이미지, 없으면 블로그 대표 이미지). 비회원이 볼 수 없는 글은 "One Blog" 기본 문구만 넣는다.
- 카카오 앱은 소셜 로그인(022)용으로 이미 있다. 웹에서 카카오톡 공유를 쓰려면 같은 앱의 **JavaScript 키**와 **사이트 도메인 등록**이 더 필요하다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - X·페이스북·텔레그램으로 공유 (Priority: P1)

공유에서 X, 페이스북, 텔레그램 중 하나를 고르면 그 서비스의 글쓰기(공유) 화면이 새 창으로 열리고, 글 주소(와 X·텔레그램은 제목)가 미리 채워져 있다.

**Why this priority**: 각 서비스가 주소만으로 공유 화면을 열어 주므로 앱 키 없이 바로 된다.

**Independent Test**: 각 항목을 눌러 열린 공유 화면에 글 주소가 들어 있고, 올린 게시물의 미리보기가 글 제목·이미지인지 본다.

**Acceptance Scenarios**:

1. **Given** 공개 블로그의 글, **When** 공유 → X, **Then** 새 창에 X 글쓰기 화면이 열리고 글 제목과 주소가 채워져 있다.
2. **Given** 같은 글, **When** 공유 → 페이스북, **Then** 새 창에 페이스북 공유 화면이 열리고 글 주소의 미리보기가 보인다.
3. **Given** 같은 글, **When** 공유 → 텔레그램, **Then** 텔레그램 공유 화면이 열리고 주소와 제목이 채워져 있다.
4. 공유 화면을 연 뒤에도 원래 글 화면은 그대로 남는다(새 창).

---

### User Story 2 - 기기 공유 (인스타그램 등) (Priority: P2)

휴대폰에서 공유 → **기기 공유**를 누르면 휴대폰의 공유 창이 뜨고, 설치된 앱(인스타그램 DM, 문자, 카카오톡, 메일 등)을 골라 글 주소를 보낸다. 인스타그램은 웹에서 링크를 받아 올리는 화면이 없어서 이것으로 대신한다.

**Why this priority**: 인스타그램처럼 웹 공유가 없는 앱까지 한 번에 닿는다. 다만 기기·브라우저가 공유 창을 지원할 때만 쓸 수 있다.

**Independent Test**: 휴대폰 브라우저에서 기기 공유를 눌러 공유 창이 뜨고, 앱을 골라 보낸 내용에 글 주소와 제목이 들어 있는지 본다. 공유 창을 지원하지 않는 PC 브라우저에서는 항목이 보이지 않는지 본다.

**Acceptance Scenarios**:

1. **Given** 공유 창을 지원하는 기기, **When** 공유 → 기기 공유, **Then** 기기의 공유 창이 뜨고 글 제목과 주소가 넘어간다.
2. **Given** 공유 창을 지원하지 않는 브라우저(대부분의 PC), **When** 공유를 열면, **Then** 기기 공유 항목이 보이지 않는다.
3. **Given** 공유 창을 연 뒤 취소, **Then** 아무 안내 없이 글 화면으로 돌아온다(오류로 보이지 않음).

---

### User Story 3 - 공유 화면 하나로 모으기 (Priority: P1)

공유 수단이 늘어나도 글 화면이 복잡해지지 않게, 글 아래의 **공유** 버튼을 누르면 공유 방법(링크 복사, X, 페이스북, 텔레그램, 기기 공유)을 고르는 작은 창이 뜬다. 링크 복사는 지금처럼 된다.

**Why this priority**: 모든 공유 수단의 입구다. 링크 복사(1차)를 그대로 지켜야 한다.

**Independent Test**: 공유 버튼 → 창이 뜨고 → 링크 복사를 누르면 지금과 같은 링크가 복사되고 안내 문구가 나온다. 창은 바깥을 누르거나 Esc로 닫힌다.

**Acceptance Scenarios**:

1. **Given** 글 화면, **When** 공유를 누르면, **Then** 공유 방법 목록이 뜨고 키보드로도 고르고 닫을 수 있다.
2. **Given** 목록, **When** 링크 복사, **Then** 지금과 같은 주소(일부 공개면 key 포함)가 복사되고 "링크를 복사했어요."가 나온다.
3. **Given** 휴대폰처럼 좁은 화면, **When** 공유를 열면, **Then** 목록이 화면 밖으로 넘치지 않는다.

---

### Edge Cases

- **비공개 블로그의 글**: 멤버만 볼 수 있어 받은 사람은 열 수 없고, 미리보기도 기본 문구만 나온다. SNS 항목은 숨기고 링크 복사만 둔다(멤버끼리 주고받기).
- **일부 공개 블로그의 글**: 링크를 받은 사람만 보는 블로그라, 여러 사람에게 공개로 올리는 X·페이스북·텔레그램 항목은 숨긴다. 링크 복사(지금처럼 key 포함)와 기기 공유(사람·채팅방을 골라 보내는 1:1 공유, key 포함)만 둔다.
- **숨김·삭제된 글**: 글 화면에 들어올 수 없으니 공유도 없다(지금과 같음).
- **팝업 차단**: 새 창이 막히면 "공유 창을 열지 못했어요. 링크 복사를 이용해 주세요."를 보여 준다.
- **미리보기 캐시**: 페이스북 등은 미리보기를 한동안 저장해 둔다. 글 제목·이미지를 고친 직후 공유하면 예전 미리보기가 나올 수 있다(서비스 쪽 동작, 이번 범위 밖).
- **로그인 여부**: 비회원도 볼 수 있는 글이면 비회원도 공유할 수 있다(지금 링크 복사와 같음).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 글 화면의 공유 버튼은 공유 방법을 고르는 목록을 연다. 목록에는 링크 복사가 항상 있다.
- **FR-002**: 어떤 항목을 보일지는 블로그 공개 범위로 정한다.
  - 전체 공개: 링크 복사, X, 페이스북, 텔레그램, 기기 공유
  - 일부 공개: 링크 복사, 기기 공유 (공개로 퍼지는 SNS 항목은 숨김)
  - 비공개: 링크 복사만
- **FR-003**: X·페이스북·텔레그램은 각 서비스의 공유 주소로 새 창을 열고, 글 주소(X·텔레그램은 제목도)를 넘긴다. 앱 키나 외부 스크립트를 쓰지 않는다. 미리보기는 글 화면의 미리보기 태그(D-59·D-66)가 그대로 쓰인다.
- **FR-004**: 기기 공유는 기기·브라우저가 공유 창을 지원할 때만 보이고, 글 제목과 주소를 넘긴다. 사용자가 취소하면 아무 안내도 하지 않는다.
- **FR-005**: 공유하는 주소는 링크 복사와 같은 글 주소다(일부 공개면 key 포함, 기기 공유만 해당).
- **FR-006**: 외부 스크립트·외부 연결을 더하지 않는다(보안 헤더 SEC-12 변경 없음).
- **FR-007**: 공유 횟수는 세지도 저장하지도 않는다(6.2). DB·서버 API 변경 없음.
- **FR-008**: 공유 목록은 키보드로 열고 고르고 닫을 수 있고(Esc, 바깥 누르기), 좁은 화면에서 넘치지 않는다.
- **FR-009**: 새 창이 막히면 링크 복사를 권하는 안내를 보여 준다.
- **FR-010**: 카카오톡은 이번 범위가 아니다. 다음 스펙(키 준비 뒤)에서 같은 목록에 항목을 더할 수 있게 둔다.

### Key Entities

없음 (저장하는 데이터 없음).

## Success Criteria *(mandatory)*

- **SC-001**: 공개 글에서 공유 버튼 → 서비스 선택까지 두 번 눌러 X·페이스북·텔레그램 공유 화면이 열린다.
- **SC-002**: X·페이스북에 공유한 글의 미리보기가 그 글의 제목과 이미지(D-59 순서)로 나온다(운영에서 한 번씩 확인).
- **SC-003**: 비공개 블로그 글에서는 링크 복사만, 일부 공개 블로그 글에서는 링크 복사·기기 공유만 보인다.
- **SC-004**: 링크 복사는 지금과 같은 주소·안내로 동작한다(기존 E2E·테스트 통과).
- **SC-005**: 휴대폰에서 기기 공유로 인스타그램 DM 등에 글 주소를 보낼 수 있다(운영에서 한 번 확인).

## Assumptions

- 공유는 글 화면만 다룬다. 블로그 화면의 "공유 링크"(일부 공개 블로그 링크 관리)는 그대로 둔다.
- 미리보기 태그는 이미 있으므로 고치지 않는다(필요하면 plan에서 확인만).
- 공유 수 집계·공유 기록 없음(6.2).

## 이번에 하지 않음

- 카카오톡 공유(키·도메인 등록 뒤 다음 스펙, 6.2 확정 사항), 블로그 화면·프로필 공유, 공유 수 집계, 미리보기 모양 바꾸기(카카오 메시지 템플릿 꾸미기)
