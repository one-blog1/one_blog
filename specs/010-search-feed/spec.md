# Feature Specification: 통합 검색·메인 피드·블로그 검색

**Feature Branch**: `main` | **Created**: 2026-10-07 | **Status**: Draft

**Input**: "010 통합 검색·메인 피드·블로그 검색 (BRD-08, BRD-09, BLG-03, 6.1, D-73)"

**관련 요구사항**: BRD-08, BRD-09, BLG-03, 6.1, D-37, D-50, D-65, D-73, D-76, D-89

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 통합 검색 (Priority: P1)

1. **Given** 메인 검색창, **When** 검색어를 넣으면, **Then** `/search?q=`에서 글과 블로그 결과가 탭으로 나뉘어 보이고 탭마다 개수가 보인다.
2. **Given** 글 탭, **When** 분류바에서 전체·제목·태그·작성자를 고르면, **Then** 그 범위로만 찾는다 (BRD-08).
3. **Given** 결과, **When** 관련도·최신·인기를 고르면, **Then** 그 순서로 보인다. 인기는 글은 좋아요 수, 블로그는 멤버 수 (D-89).
4. **Given** 결과가 없으면, **Then** "검색 결과가 없습니다".

### User Story 2 - 블로그 검색 (Priority: P1)

1. **Given** 블로그 탭, **When** 검색하면, **Then** 이름·소개(FULLTEXT)와 블로그 태그(일치)로 찾는다 (BLG-03).

### User Story 3 - 메인 피드 (Priority: P1)

1. **Given** 메인 화면, **When** 열면, **Then** 전체 공개 블로그의 최신 글과 인기 글을 탭으로 본다.
2. **Given** 로그인한 회원, **When** 팔로우·구독 탭을 누르면, **Then** 팔로우한 회원의 글, 구독한 블로그의 글을 따로 본다 (D-65).

### User Story 4 - 최근 검색어 (Priority: P2)

1. **Given** 로그인한 회원, **When** 검색하면, **Then** 최근 검색어 10개가 남고, 하나씩 또는 모두 지울 수 있다 (6.1).

### Edge Cases

- 검색어는 앞뒤 공백을 빼고 2~20자, 글자나 숫자가 있어야 한다. 빈칸·특수문자만이면 거부 (6.1).
- FULLTEXT 검색식 기호(+, -, ", * 등)는 지운다. 사용자가 검색식을 조작할 수 없다.
- 결과에서 빠지는 것: 전체 공개가 아닌 블로그, 숨김·폐쇄 블로그, 숨김·삭제 글. 차단한 회원의 글은 013에서 `SearchFilter`로 뺀다.
- 팔로우·구독 탭에서도 내가 볼 수 없는 블로그의 글은 빠진다(멤버가 아닌 비공개 블로그, D-37). 구독한 일부 공개 블로그의 글은 보인다 (D-50).

## Requirements *(mandatory)*

- **FR-001**: 블로그 이름·소개와 글 제목은 FULLTEXT ngram(BOOLEAN, 낱말마다 필수), 태그와 닉네임은 일치 검색 (BRD-08).
- **FR-002**: 한 페이지 10·20·30개, 번호 페이지 (D-76).
- **FR-003**: 피드는 볼 때마다 모아온다(피드 테이블 없음, D-73).
- **FR-004**: 최근 검색어는 첫 페이지를 볼 때 남기고, 같은 검색어는 시각만 새로 한다. 본인 것만 보고 지운다.

### Key Entities

- **최근 검색어(recent_searches)**: ERD 그대로.

## Success Criteria

- **SC-001**: 검색·피드(전체 탭)에 전체 공개가 아닌 블로그의 글이 나오지 않는다.
- **SC-002**: 목록·검색은 1~2초 안에 응답한다(4.2). 넘으면 피드 테이블을 다시 검토한다 (D-73).
